Rate Limit

Batas request per menit

Di halaman ini
  • Klien Otomatis
  • Header Response
  • Response 429
  • Catatan

Batas dihitung per alamat IP dengan jendela tetap 60 detik. Hitungan di-reset saat jendela berganti

KelompokEndpointNormalKlien otomatis
lookup/api/tiktok, /api/{link}, /api/user, /api/hashtag, /api/30 per menit12 per menit
download/api/download60 per menit15 per menit
-/api/healthTanpa batasTanpa batas
Semua endpoint kelompok lookup berbagi satu hitungan yang sama. Satu request profil, hashtag, atau video masing-masing memakai jatah 30 per menit yang sama

Klien Otomatis#

Request dianggap klien otomatis jika User-Agent kosong, kurang dari 10 karakter, atau mengandung nama tool umum seperti curl, wget, python-requests, axios, node-fetch, undici, okhttp, Postman, dan sejenisnya. Klien seperti ini mendapat batas yang lebih ketat seperti pada tabel

Scanner keamanan (misalnya sqlmap, nikto, nmap) selalu ditolak dengan status 403

Header Response#

HeaderIsi
ratelimit-limitBatas untuk request ini
ratelimit-remainingSisa jatah pada jendela berjalan
ratelimit-resetDetik sampai jendela berganti
retry-afterDetik yang harus ditunggu, hanya pada status 429

Response 429#

429
{
  "code": -1,
  "msg": "Terlalu banyak permintaan. Coba lagi sebentar lagi."
}

Tunggu selama nilai retry-after lalu ulangi. Contoh penanganan otomatis ada di setiap panduan bahasa

Catatan#

  • Download tidak dibatasi ukuran file maupun durasi video, hanya dibatasi jumlah request
  • Pada deployment tanpa Redis, hitungan disimpan di memori tiap instance sehingga bisa terpisah antar instance. Redis (Upstash) bersifat opsional dan hanya perlu diatur oleh pemilik deployment
